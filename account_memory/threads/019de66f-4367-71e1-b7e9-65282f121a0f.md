## 助手结果摘录

### 助手结果摘录 1

Telnet 卡住大概率是上一段命令里的引号/换行让 shell 进入了“等待继续输入”的状态。

先在 Telnet 窗口里按：

```text
Ctrl + C
```

如果没反应，再按一次回车。还不行就退出 Telnet：

```text
Ctrl + ]
```

出现 `telnet>` 后输入：

```text
quit
```

然后重新连：

```powershell
telnet 100.82.136.106 23
```

登录后这次不要粘复杂脚本，先执行最简单的修复权限。逐行粘贴，每粘一行按回车：

```sh
sudo -v
```

然后：

```sh
sudo chown root:root /etc/ssh/force_command.sh
```

```sh
sudo chmod 755 /etc/ssh/force_command.sh
```

```sh
sudo chmod 755 /etc/ssh
```

```sh
sudo sed -i 's/\r$//' /etc/ssh/force_command.sh
```

```sh
ls -ld /etc/ssh /etc/ssh/force_command.sh
```

最后一条输出里必须看到类似：

```text
drwxr-xr-x ... /etc/ssh
-rwxr-xr-x ... /etc/ssh/force_command.sh
```

然后执行：

```sh
sudo sshd -t
```

如果没输出，再执行：

```sh
sudo systemctl reload sshd
```

再回 PowerShell 测：

```powershell
ssh 18913391330@100.82.136.106
```

我们先把 `Permission denied` 修掉，比继续改 `ForceCommand` 配置更稳。现在的问题就是脚本存在但不可执行。
