### 助手结果摘录 3

这次日志的重点不是报网络错，而是：

`Interrupted during API call.`

意思是：**它已经开始向模型/API发请求了，但请求过程中被打断了**。  
这通常不是“不会调用工具”，而是下面两种更常见：

1. 你在它还没答完时，又发了新消息  
2. Gateway/容器刚重启过，上一轮请求被中断了

再结合你配置里之前有：

`busy_input_mode: interrupt`

这就更像是：**新消息把上一轮强行打断了**。

### 助手结果摘录 4

### 助手结果摘录 5

查清了，`busy_input_mode` 只有两个有效值：

- `interrupt`：新消息打断当前任务
- `queue`：新消息排队，等当前任务做完

你现在用的是：

```yaml
busy_input_mode: interrupt
```

这就是为什么容易出现 `Interrupted during API call.`。

先把它改成 `queue`。在 NAS 上直接执行：

```bash
sudo python3 - <<'PY'
from pathlib import Path
import yaml

p = Path('/volume1/docker/hermes-agent/hermes/config.yaml')
cfg = yaml.safe_load(p.read_text(encoding='utf-8'))

cfg.setdefault('display', {})
cfg['display']['busy_input_mode'] = 'queue'

p.write_text(yaml.safe_dump(cfg, allow_unicode=True, sort_keys=False), encoding='utf-8')
PY
```

然后重启：

```bash
cd /volume1/docker/hermes-agent
sudo docker compose up -d
```

再确认一下：

```bash
sudo grep -n 'busy_input_mode' /volume1/docker/hermes-agent/hermes/config.yaml
```

应该看到：

```yaml
busy_input_mode: queue
```

然后测试时注意两点：

1. 开日志用一个窗口：
```bash
sudo docker logs -f hermes
```

2. 微信里只发一条消息，发完至少等 30 到 60 秒，不要再发第二条

测试文本继续用这句：

```text
现在是 2026年4月24日。请必须先联网检索再回答：今天美元兑人民币实时汇率是多少？如果没有真实检索结果，就只回复“检索失败”，不要猜。
```

补一句，你截图里最后的 `^C` 是你手动中断了日志跟随，这个本身没问题。  
但之前那条 `Interrupted during API call.` 很大概率就是 `interrupt` 模式把正在跑的请求切断了。改成 `queue` 是对的。
