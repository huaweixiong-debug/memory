## 1. 命令注入漏洞（严重）

`claude-api.js:24`

```js
const command = `claude -p "${prompt.replace(/"/g, '\\"')}" --print`;
```

用户输入的 `prompt` 被直接拼接到 shell 命令中，仅对双引号做了转义。这**不足以**防止命令注入。攻击者可以利用反引号、`$()`、分号等 shell 元字符执行任意命令。

**攻击示例：**
- `$(rm -rf /)` — 命令替换执行
- `` `rm -rf /` `` — 反引号执行
- `"; rm -rf /; echo "` — 分号分隔执行

**修复方案：** 使用 `execFile` 或 `spawn` 并传参数组，避免经过 shell 解析：

```js
const { stdout, stderr } = await new Promise((resolve, reject) => {
  const child = require('child_process').spawn('claude', ['-p', prompt, '--print'], {
    timeout: 120000,
    env: { ... }
  });
  // ...
});
```

---

## 2. 敏感信息泄露（中）

`claude-api.js:42` — 错误消息直接返回给客户端：

```js
res.status(500).json({ error: error.message });
```

这会导致内部错误详情（如文件路径、环境信息）暴露给外部。生产环境中应返回通用错误消息，将具体错误记录到日志。

---

## 3. Token 传递风险（低-中）

`claude-api.js:30` — `ANTHROPIC_AUTH_TOKEN` 直接作为环境变量传入子进程。如果 CLI 在错误日志中打印环境信息，token 可能被泄露。

---

## 4. 缺少基础防护

- 无**请求体大小限制** — 可以发送超大 prompt 导致服务异常
- 无**速率限制** — 没有防御滥用的机制
- 无**请求日志**级别的区分 — 所有错误都走 `console.error`，缺乏结构化日志

---

**总结：命令注入是最紧迫的问题**。当前代码将用户输入直接拼接到 shell 命令中，任何能够调用 `/claude` 端点的人都可以在服务器上执行任意命令。需要我帮你修复这些问题吗？
