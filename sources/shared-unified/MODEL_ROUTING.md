# MODEL_ROUTING — 三方 Agent 统一模型路由规则

> 适用范围：Codex、ZCode、OpenCode。本文件由 `sources/shared-unified/` 维护，`README.md` 仅负责入口发现。
> 生效日期：2026-09-03。本文件只定义模型路由；其他主题或冲突按仓库统一规则与最新、最具体的明确来源处理。

## 1. 目标

- 用最低合理成本完成日常任务：小任务默认走低成本模型，不无谓消耗高阶额度。
- 在失败、复杂度或风险升高时，按明确的升级阶梯换用更强模型/更高推理档位，而不是反复重试。
- Sol（架构/疑难/上线前终审专用模型）保持限定场景，避免被常规任务占用。

## 2. 原则

1. **验证不可跳过**：禁止为省额度省略验证步骤（测试、lint、编译、启动检查等）。验证失败不是"可以跳过"的理由，而是"应当升级"的信号。
2. **升级基于证据**：升级触发以可观察事实为准（连续失败、任务复杂度、风险领域），不以主观疲惫或猜测为准。
3. **降级回归默认**：升级解决后，后续同类任务回到默认路由，不长期驻留高配。
4. **记录升级原因**：会话中若发生升级，最终结论需注明原因，便于沉淀到 memory。

## 3. 默认路由

| Agent | 默认模型 / 档位 | 默认场景 |
| --- | --- | --- |
| Codex | **5.6 Luna**（低成本默认）→ **5.6 Terra**（复杂/疑难）→ **5.6 Sol**（裁判/终审） | Luna 负责常规编码、文档整理、memory 维护和单文件小改；Terra 处理复杂度上升；Sol 只做裁判 |
| ZCode | **GLM-5.3-Flash**（低成本、高吞吐默认） | 大量执行、长任务和常规仓库工作 |
| OpenCode | **GLM-5.3-Flash**（低成本、高吞吐默认） | CLI、自动化、多 Agent 和执行型工作 |

低成本默认是第一选择：先按默认路由执行并验证；验证通过即结束，不追加升级。

## 4. 升级阶梯

升级时逐级上移，每次只升一级，并说明触发条件：

1. **Level 0（默认）**：低成本模型按默认档位执行。
2. **Level 1（提高推理档位）**：同一问题**连续失败** 2 次（同一根因、同一切片），或任务为跨文件复杂任务时，提高 reasoning effort（如 `medium` → `high`），保持同一模型。
3. **Level 2（切换更强通用模型）**：Level 1 仍失败，或出现**原因不明 Bug**（复现路径不清、日志互相矛盾、疑似环境/并发问题）时，Codex 从 Luna 升到 **Terra** 重新诊断；ZCode/OpenCode 以同等能力层级的更强可用模型替换默认模型。
4. **Level 3（Sol 终审）**：仅在以下场景启用 Sol，并须满足当前平台的授权/审批要求或用户明确请求：
   - 架构决策与蓝图终审（如 PLAN_FINAL 评审）；
   - 反复升级后仍无法定位的疑难问题；
   - 上线前 / 高风险变更（数据迁移、删除逻辑、支付与凭据相关）最终把关。

## 5. 任务类型规则

| 任务类型 | 路由 |
| --- | --- |
| S：单文件、低风险、边界清晰 | 默认低成本模型 + `medium` |
| M：多文件、需规划 | 默认模型 + `high`，或按计划评审结果执行 |
| L：**大重构**、架构调整、跨模块职责重划 | 规划阶段由 Terra（或较强模型）评审蓝图；实现可用默认模型分切片执行；终审走 Sol |
| 疑难调试：**原因不明 Bug**、复现困难 | 直接 Level 2 起步 |
| 高风险领域（权限/支付/数据一致/删除逻辑） | 提高审查强度，终审走 Sol |
| 纯文档 / memory 维护 | 默认低成本模型 |

## 6. 执行检查清单

每次任务开始前确认：

- [ ] 已按任务类型选定路由与档位，未无谓超配。
- [ ] 验证方案明确（验证命令、成功标准），且不会被省略。
- [ ] 出现连续失败时已升级，而不是重复原样重试。
- [ ] 大重构/高风险任务已走规划评审与 Sol 终审。
- [ ] 升级与结论已按要求沉淀到共享 memory（无凭据、无原始对话）。
